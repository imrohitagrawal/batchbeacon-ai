# Owned source replay and trusted currentness runtime

The source runtime separates incident-owned historical replay from trusted global
refresh. Its strict catalog binds the genuine UK original/update captures to
versions, dates and subnational scope. UK interpretation remains unapproved:
parent/company-PDF lot and date applicability and source context are unresolved.
The catalog contains no approved UK product predicates or model agreement.

An explicit source review creates a separate empty owned investigation and selects
the original notice. Forward selection adds Wales and Scotland, preserves history
and removes the active result. Reverse replay is refused. Original keys reconcile
partial creation and uncertain acknowledgements; a different key for the same
logical transition adds a receipt without advancing the selection again. Session
references prevent a saved creation request from moving to another owner.

Trusted refresh is an operator-only module with no public endpoint. A configured
fixed HTTPS URL uses pinned public peers, verified authority TLS, finite total
network/byte/retry bounds and no redirects or proxy fallback. Only raw HTTP bodies
can be compared with raw captures. Retained UK rendered text cannot be compared
with fresh HTML. Network and model operations never run in transaction callbacks.

Before fetching, a durable family journal marks the source unavailable. Publication
checks journal ownership and deadline transactionally. Retained baselines survive
failed and expired attempts; retries and duplicate bodies cannot double the epoch.
Changed, unavailable, pending and expired evidence cannot regain historical
eligibility. Every dependent result, action, acquisition completion, retail row and
guidance activation resolves current source state. Previous negatives and recorded
actions remain historical when their basis changes.

No successful retrieval timestamp is bound to the retained UK captures. It remains
explicitly unknown; failed-fetch receipts, file times and review times are not
substitutes. Unknown retrieval is accepted only for unreviewed, incomplete notices.
Reviewed or complete notices still require a known timezone-aware timestamp.

The UI discloses unknown retrieval, exact selected versions and scope, review-only
status, creation effects and saved-operation recovery. Manual status checks read
saved records without an authority fetch or AI request. Pending source keys survive
reload, temporary context failure and replay-disabled operation. Unrelated ready
work preserves that key; navigation cannot replace the displayed case or claim
that unread evidence was refreshed. Actual VoiceOver speech and unfamiliar-user
comprehension remain separate human evidence.

Activation requires the final nullable-compatible image serving at 100% followed
by the complete request drain before **any** new null-bearing cloud fixture or
registry record. The earlier preparatory reader cannot read this new null value.
A compatible rollback must use the final image with the same catalog admission and
replay disabled; old images or the original configuration cannot replace that
reader after owned source selections exist. Rollback must preserve pending keys
and allow saved-state reconciliation, then resume the original request after
replay is restored.

Controlled tests cover forward replay, logical deduplication, owner/expiry denial,
partial creation, lost acknowledgements, pending recovery, source-refresh outcomes,
fixed-peer transport refusal/deadlines, positive/negative invalidation, approval,
acquisition publication and guidance races. Local, emulator, real service, actual
source fetch, hosted, build, deployed and rollback evidence are separate gates.
The immutable UK receipt and runtime implementation do not constitute human source
approval, genuine UK matching acceptance, protected evaluation or submission.
