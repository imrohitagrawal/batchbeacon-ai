# Production composition and private deployment preparation

The explicit runtime factory composes actual Firestore and private Storage SDKs,
the reviewed SFA source/identity loader, bounded ADK extraction, owned evidence,
simulated actions, retail queue and persistent guidance lifecycle. Startup never
creates an environment, initializes an allowance or activates a paid phase.
Missing or inconsistent configuration fails before credential discovery. A
separate closed mode exposes only cheap health while a private service origin is
being established; it has no guest or model routes.

Independent verification passed ten offline checks, including one reproduced
configuration-order correction. Inconsistent acquisition deadlines/limits now
fail before ADC. Capacity observations read the actual shared ledger, phase,
price validity and active-run state; unavailable/unknown state cannot authorize
capture guidance. Per-incident lifetime limits remain independently enforced.
These checks do not establish deployed IAM or real guidance execution.

The reviewed container candidate pins Python 3.12.13, uv 0.11.18 and the Docker
builder by verified Linux/amd64 manifest digests. Build context is an explicit
59-file allowlist with locked dependencies, application assets, synthetic labels,
fixed learning inputs and individually admitted original SFA source assets. No
private directory, credential, guest capability, raw attempt or H case enters
the context. Runtime is non-root; no image build/deployment is claimed here.

The provider budget API is enabled. Actual project-scoped inventory was empty;
three budgets now exist and were read back: INR4,800 funded-period operating
alerts, INR2,500 monthly Vertex spend cap and INR400 monthly Cloud Run spend cap.
Both service caps report CONFIGURED. Native project-owner/billing-admin recipient
behavior applies; no custom recipient or test notification was sent. A response
omitted protobuf's zero-nanos default; the local verifier initially rejected the
shape, then reconciled the already-created budget before creating the other two.
No duplicate budget was created. Calendar caps/reporting lag do not replenish or
replace the application's lifetime pools and are not instantaneous project caps.

Dedicated runtime, build and deploy identities, one private regional Docker
repository and one private build-source bucket now exist. Twenty bounded create/
binding operations were read back against the reviewed least-privilege candidate.
The bucket has uniform access, public-access prevention and a one-day live-object
deletion rule with seven-day soft retention. Earlier immediate service-account
read lag was reconciled before further creation; no duplicate was created.
No runtime billing, deployment or IAM administration privilege was granted.

Actual private build, attached runtime identity, controlled ledger carry-forward,
source/environment bootstrap, deployed browser/isolation and Operations acceptance
remain separate gates. Current production configuration does not prove these.
Detailed manifests, failed evidence and resource identities remain under ignored
`.local/builds/` and `.local/run-records/new-primary/`.
