# Unconfirmed-check operator procedure

Responsible operator: the BatchBeacon project owner. No public support channel
is configured or tested. A dedicated owner-controlled support address is the
recommended next route; choosing/publishing it and verifying receipt require the
owner’s destination decision. Public GitHub Issues is not the default for case
records: this repository is public, and issue access is not separately private.
[GitHub issue-access documentation](https://docs.github.com/en/repositories/creating-and-managing-repositories/creating-an-issues-only-repository).

Until then, the interface must say that no notification was sent and no response
period is promised. The copyable case reference is an identifier, not a credential.
It must not contain cookies, tokens, provider bodies or private logs. Saved labels
and the exact official notice remain available only while owned access is valid.

When an approved private channel is operational:

1. Ask for the displayed case reference, observed message and whether access is
   still active. Do not request authentication cookies or tokens. Explain the
   non-production sample scope; do not ask the visitor to publish private logs.
2. Inspect owned incident/run/completion records and the original attempt’s bound
   request, response, usage, configuration, grant and rate evidence privately.
   Distinguish incomplete execution, unsupported usage, accepted completion and
   already-settled failure. A timeout or HTTP 200 alone is not settlement proof.
3. Preserve all reservations and failed evidence. Do not use new keys, a fresh
   workspace, longer deadlines or an assumed zero charge to erase unknown liability.
   No further paid AI calls are authorized by this procedure.
4. If existing evidence permits a supported recovery, prepare its precise record
   preimages/postimages, concurrency/idempotency guards and original-liability
   compatibility proof. Obtain independent technical review and apply only within
   a separately admitted operational scope. Missing proof remains unresolved.
5. Tell the visitor to use Recheck saved status. This GET observes completion and
   availability; it neither calls AI nor performs settlement. Expired access
   cannot be restored through the UI, and a new workspace does not inherit cases.
6. Verify delivery and the user-visible readback before claiming that this route
   works. Record observed receipt and outcome separately from configuration.

The current F8 diagnosis needs a bounded cache-accounting compatibility analysis
using retained bytes and current official pricing/schema evidence, separate from
the prior deadline hypothesis. No change to billing interpretation, reservations,
current runtime or provider deadlines is part of the user-journey UI correction.
