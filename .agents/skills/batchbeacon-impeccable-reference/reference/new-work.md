# Replacement A treatment

Modified from Impeccable new-work.md; see ../PROVENANCE.md and ../LICENSE.
Start with the familiar product shell and task hierarchy: session shop queue,
incident evidence and comparison, then explicit simulated action confirmation.
Use one coherent palette, fixed type scale and aligned spacing. Define one useful
signature: an evidence-to-predicate comparison grid where uncertainty is visible.
Keep data and controls recognisable; avoid a decorative instrument costume.

Build a reversible native HTML/CSS prototype. Include desktop and phone capture,
readable source facts, targeted recapture, source-update invalidation, review-only
outcomes, owned retail queue and feedback/candidate/evaluation/activation/rollback.
All illustrative data and nonpersistent controls must be plainly labelled.

Render and inspect the actual artifact, including keyboard focus, reduced motion,
empty, loading, failure and stale states. Obtain the already-required concrete
owner visual approval before final DESIGN or production visual integration.
No publisher catalog, concept tournament, image provider, seed, binary, agent,
decision server or auto-written design sidecar is required in this adapted mode.
